## Services and logs

<Tabs syncKey="os">
<TabItem label="Linux">

```bash
systemctl status craftpanel craftpanel-runtime
journalctl -u craftpanel -f              # dashboard
journalctl -u craftpanel-runtime -f      # Minecraft runtime
sudo systemctl restart craftpanel        # restart the dashboard; games keep running
```

</TabItem>
<TabItem label="Windows">

- The dashboard runs as the scheduled task **CraftPanel** and starts at sign-in.
- Minecraft runs in the Windows service **CraftPanel Runtime** and starts at boot.
- Logs are in `%LOCALAPPDATA%\CraftPanel\logs`.

</TabItem>
</Tabs>

Restarting the dashboard never stops Minecraft. Restarting the **runtime** saves and stops all servers; those with **Start with CraftPanel** come back automatically.

## Tasks after a restart

**Activity → Tasks** lists the long operations: installations (also after a software or version change), server backups, restores and application backups. Each shows its progress while it runs and its result afterwards. Owners also see application backups there; other users see tasks of the servers they can see. Tasks are kept for 30 days.

If the dashboard stops while a task runs (an update, a crash, a reboot), the task resumes or ends cleanly when it starts again:

- An **installation** resumes on its own, once, and is marked **Resumed after a restart**. If it is cut short a second time, it is marked interrupted; retry it from the server's page.
- A **server backup** or an **application backup** is marked interrupted. Its unfinished file is removed; start it again.
- A **restore** is marked interrupted. The server's files may be incomplete, so restore the same backup again, or the safety copy taken just before it (**pre-restore** under Backups), before starting the server.

## Stopping everything

**Settings → Security & about → Stop all servers for maintenance** saves and stops every server, for example before maintenance on the machine. Auto-start settings stay as they are for the next boot. On a normal shutdown or reboot, the runtime does this by itself.

## Backing up CraftPanel

Server backups protect your worlds. To back up the panel itself (accounts, settings, schedules, all servers), create an **Application backup** under **Settings → Backups** and download it. It works while CraftPanel runs and needs no copying of files by hand.

If you prefer to copy files yourself:

1. Stop the dashboard **and** the runtime.
2. Copy the whole data directory.
3. Copy your settings file and any TLS certificates and keys.

Copying only the database file while CraftPanel runs can miss recent changes.

## Moving CraftPanel to another computer

1. On the old computer, create an application backup **with server files and worlds** (Settings → Backups) and download it.
2. Install CraftPanel on the new computer. On its welcome screen, choose **Restore a backup instead**, upload the file and enter its passphrase if encrypted. A network installation also asks for the setup token from the log or `setup-token.txt`.
3. Wait for restoration, then choose **Sign in with the restored account**. Use your old account and two-factor sign-in. Servers download their game files again and start if they had automatic start.

Choose **Include earlier server backups** when creating the archive if you want to carry the server backup history too. Only completed backups with available local files are included. Without that option the earlier-backup list starts empty. **Encrypt with a passphrase** protects the archive; keep that passphrase separately, since it cannot be recovered. Encrypted backup schedules are paused after a move: edit each schedule and enter its passphrase again before enabling it.

The browser accepts files up to **2 GB** and requires a fresh installation with no accounts or game servers. It checks the archive before changing the installation. An activation failure rolls back; if recovery cannot finish, keep the recovery files and restart CraftPanel.

### Offline import

For larger files or an existing installation, stop the dashboard **and** the runtime. Copy the file there and import it as the account CraftPanel runs under, with the same settings as the service (`--env-file` or the service's environment):

<Tabs syncKey="os">
  <TabItem label="Linux">
```bash
sudo systemctl stop craftpanel craftpanel-runtime
sudo -u craftpanel env CRAFTPANEL_DATA_DIR=/var/lib/craftpanel node /opt/craftpanel/apps/api/dist/index.js import-backup /tmp/craftpanel-app-….zip
sudo systemctl start craftpanel-runtime craftpanel
```
The file must be readable by the `craftpanel` account. If the installer put its own Node.js in `/opt/craftpanel/node`, use `/opt/craftpanel/node/bin/node`.
  </TabItem>
  <TabItem label="Windows">
```powershell
# Run as the account that installed CraftPanel, from its installation folder.
Stop-ScheduledTask -TaskName "CraftPanel"
Stop-Service -Name "CraftPanel Runtime" # elevated shell, if installed as a service
$env:CRAFTPANEL_DATA_DIR = "$env:LOCALAPPDATA/CraftPanel"
node apps/api/dist/index.js import-backup C:/Backups/craftpanel-app-….zip
Start-Service -Name "CraftPanel Runtime"
Start-ScheduledTask -TaskName "CraftPanel"
```
Use the installation's actual task name and data directory (`install.json`) if you chose different ones. Starting and stopping the runtime service needs an elevated shell; run the import as the dashboard's account. If this is a manual checkout, stop both Node.js processes and use that checkout's data directory instead.
  </TabItem>
</Tabs>

For an encrypted `.cpbackup` file, add `--passphrase-file /path/to/private-file`. Put only the passphrase in that UTF-8 file (one trailing newline is accepted), make it readable only by the dashboard's account and remove it afterwards. Avoid putting the passphrase in the command line or an environment variable.

Start CraftPanel and sign in with your old account. Every server downloads its game files again (the backup carries worlds and configuration, not the Minecraft jar) and starts if it had automatic start.

What changes on the way: sessions end (sign in again), server folders live in the new data directory, the Java path and a bind address of the old computer are cleared, and a custom backup folder has to be chosen again. First-run restoration keeps the new host's dashboard access policy. The old `CRAFTPANEL_*` settings and certificate are saved in `import/` in the data directory for you to apply (they hold paths of the old computer). Offline import into a data directory that already has an account needs `--replace`, which moves the current database and server folders aside instead of deleting them. A backup from a newer CraftPanel than the one installed is refused: update first.

<Aside type="note">
Updates keep their own recovery points (database snapshot and startup files) under the installation folder and restore them if an update fails. They don't include worlds and are not a replacement for backups.
</Aside>

## Uninstalling

- **Linux:** `curl -fsSL https://github.com/vctrchappot/CraftPanel/releases/latest/download/install.sh | sudo bash -s -- --uninstall`
- **Windows:** `$env:CRAFTPANEL_UNINSTALL = "1"; irm https://github.com/vctrchappot/CraftPanel/releases/latest/download/install.ps1 | iex`

Both keep your data directory and settings. Delete them by hand if you no longer need your servers.
