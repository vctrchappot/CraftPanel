## The Performance tab

Everything about how a server runs lives in one tab, **Performance**, next to Console and Settings:

- **Insights**: a short, ranked list of what the live numbers and your settings say, with a one-click fix where there is one (for example a view distance that suits the machine, tuned garbage-collector flags, or a memory size the machine can spare). It says "Running smoothly" when there is nothing to flag.
- **Performance overview**: each card combines a current reading with its chart, time axis and average, low or peak for the selected 5-minute, 15-minute or 1-hour range. TPS and tick time come first, followed by CPU, memory and players. Hover or touch a chart for the exact value and time. Tick time has its 50 ms budget marked; CPU shows 100 % as one core; memory shows process memory against the configured Java heap. The status badge distinguishes live readings from the last recorded run.
- **Tuning**: compare presets side by side, then adjust memory or pre-generate the world. Expand **JVM arguments** for Java flags, or **Advanced server settings** for the performance settings from `server.properties` (view and simulation distance, watchdog, entity broadcast range, chunk saving). Configuration changes apply on the next start.

CraftPanel samples a server only while a dashboard has it open, and keeps about an hour of samples in memory since the last start. A gap in a chart means nobody was watching; a restart of CraftPanel clears the history. Memory is what the Java process uses in total, which is a little more than the heap you allocate. Tick times need Paper, Purpur, Fabric or NeoForge; Vanilla reports them from 1.20.3, and a Velocity proxy shows CPU, memory and players only.

## Presets

A preset sets Aikar's garbage-collector flags sized to the server's memory, plus view and simulation distance:

| Preset | For | View / simulation distance |
| --- | --- | --- |
| **Raspberry Pi / small VPS** | Few cores, little memory | Short |
| **Balanced** | A typical desktop or mid-size VPS | Medium |
| **Powerful machine** | Many cores, plenty of memory | Long |

The wizard preselects the preset recommended for this machine. Change it later in the server's **Performance** tab; your own JVM arguments are kept.

## Does it fit this machine?

CraftPanel looks at the machine it runs on (cores, memory, a Raspberry Pi or other board model, and a container's memory limit) and at your plan: the software, the player slots, the view distance, a modpack and the servers that already run. In the wizard's **Resources** step one card says whether the plan fits, is tight or is too much, and suggests a memory size; the Performance tab raises the same finding in its insights and shows the suggestion next to the memory slider. Nothing extra is asked, and the memory slider follows the plan until you move it yourself.

The numbers are rules of thumb for Paper-class servers, not a guarantee: about 60 % of the player slots are assumed to be online at once, and the CPU estimate only separates small boards from desktops and large hosts. The Performance tab shows what the server really uses once it runs.

## Memory

Give the server what it needs, not everything the machine has. The operating system and CraftPanel need room too.

| Server | Suggested memory |
| --- | --- |
| Vanilla or Paper, a few friends | 2 GB |
| Paper with many plugins, 10–20 players | 4 GB |
| Fabric with performance mods | 2–4 GB |
| NeoForge or a modpack | 4–8 GB |

The memory chart in the Performance tab shows what the server really uses, so you can see whether it is short on memory.

## Pre-generating the world

Generating new chunks while players explore is the most expensive thing a server does. **Performance → Pre-generate the world** installs [Chunky](https://modrinth.com/plugin/chunky) with one click (Paper, Purpur, Fabric and NeoForge) and generates a radius around spawn ahead of time. You can follow the progress, pause, continue or cancel.

<Aside type="tip">
On a Raspberry Pi, pre-generate a modest radius (for example 1,000 blocks) overnight before inviting players.
</Aside>
